# FON-571 SDK candidate

Base: `334af775efe4b9266ab5262de20139ac114aaad2`. Candidate packages:
Core/React/Next `0.2.0-fon571.0`; CLI version and behavior are unchanged.

This is a breaking collection-contract candidate. An installation must supply
an approved policy and its collector must parse `fonte.acquisition.v1` and
return explicit durable receipts. Missing policy disables capture; legacy
HTTP success does not become acceptance. No npm publication is performed.

The change repairs URL-based occurrence reuse, mutable retry evidence,
forwarding-time ambiguity, cookie-derived false Meta encounters, X hostname
matching, typed click IDs, and unbounded full-body parsing. It also fixes two
reproduced browser problems: stale Next/React history wrappers could capture
one navigation twice, and fragment traversal emitted both popstate and
hashchange for one occurrence. Explicit reset clears persisted continuity
after a document reload and invalidates pending responses.

Build and strict Core/React/Next checks pass. The 35 focused tests in
`acquisition-regression`, `core`, `nextjs`, `react`, `public-types` and
`package-boundaries` pass. Web installs the actual tarballs and runs the real
Chromium lifecycle test. Full repository readability is blocked by unchanged
CLI/scripts/tests; changed acquisition files have no reported violation.

The implementation receipt in fonte-web (`docs/fon571-implementation-receipt.md`)
records exact installed hashes and PostHog retained synthetic proof. FON-571
stays open: current-runtime durable idempotency, issued-link resolution,
authenticated linkage, erasure and an organic-arrival-through-signup proof
remain unimplemented/unqualified. Local response fixtures do not establish
those properties. The sanctioned installation binding and approved collection
policy are still missing; no legacy quarry or substitute authority is enabled.
