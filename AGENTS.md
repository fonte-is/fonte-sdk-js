# Fonte SDK JS

Public-launch source contract: the shared Fonte SDK, CLI, MCP, HTTP clients,
onboarding, examples, and package exports express Fonte operations, not
suppliers. Use Fonte concepts for connections, contact import, identity,
successful actions, commerce, and Results. Do not expose vendor-specific
methods, commands, types, configuration, or default tutorials. Optional
supplier adapters are implementation details; identify the actual supplier only
where account authorization/selection, provenance, or required notices need it.

Fix the underlying model rather than renaming a provider-shaped method.
Remove bad prerelease public APIs instead of adding compatibility shims.
Keep copy/import distinct from audience freeze; retain real connection scope,
unsupported capabilities, identity mapping, replay/coverage, privacy, and
qualified collected-money semantics. Do not add a parallel framework or
release ceremony. Match the actual built package and public customer journey.

The SDK repository is public. Browser code must be safe on customer sites,
with no server credentials or supplier secrets in shipped browser bundles.

Run focused tests and the build for the changed packages.
