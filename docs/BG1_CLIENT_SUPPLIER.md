# BG-1 product client supplier

This source supplier uses SDK shared main `37cdf78c92e1799a4c779733c4cd7309f1d7c6df`, verified by read-only GitHub `ls-remote` and fetch on 2026-09-26. The supported normal entrypoints are `broadcast send --send-input` and `fonte_send_broadcast`. The existing retired `send now` handler and scheduling/control handlers are unchanged.

The public wire projection follows Core FON-807 at `f9669b03ce1e50568d2aa3d63ed78a2c2aef3902`, `src/modules/broadcasts/break-glass-contracts.ts`, and its `test/fixtures/break-glass-conformance.ts`. The two fixture review digests (2,048 and zero recipients) are actual outputs of that Core helper. Clients validate exact wire fields, scope, operation URI, counts, authority flags and sizes. They retain opaque producer commitments; they do not compute a new review, audience, route, commercial or execution digest.

The reference-only store records Core origin, immutable workspace ID, workspace code, environment, draft ID and the exact request. It atomically publishes and fsyncs immutable input before POST. The authenticated workspace resolver must resolve the user-selected code to the actual immutable ID. A rebound code or different same-key payload blocks before mutation. The store contains no authorization token, message body, recipient list, assignment array or billing policy. Corrupt/legacy saved inputs return `broadcast_saved_input_recover_review_required`; they are not converted into another Send.

Response loss preserves `core_effect: unknown` and the request ID. Recovery replays the same immutable request key, both before and after an unknown commit. It never treats an absent read as evidence that the original request cannot commit. A server `request_superseded` receipt is durably remembered; later fresh-process recovery displays that receipt without POSTing the old input. An explicitly approved new review uses `approvedBroadcastSendInput` with a new request ID and `resume: {operationId, expectedOperationVersion}` to revise the same unstarted operation. The helper never generates keys or approvals.

BG transport uses one default 60,000 ms ceiling for review POST/read, Send POST/read and recovery. `--request-timeout-ms` / MCP `request_timeout_ms` explicitly override it. `--wait-ms` / MCP `wait_ms` separately bound foreground read-only polling; deadline returns pending with the last operation ID. The returned operation URI must stay on configured Core origin. Compact request/store/response validation is capped at 65,536 bytes. Processing/action-required/rejected results cannot print Sending or completed; an executable receipt is labeled an executable job, with completion shown only from actual execution progress.

## Root composition seams

Root owns shared parser/runtime/MCP session/package exports. This supplier intentionally does not edit release launchers, release command files, package activation/version or FON-800 tests.

- `broadcast-command.ts`: call `parseBroadcastArguments` before the existing normal Send parser; route returned commands to `runBroadcastCommand` and `renderBroadcastCommand`. Invalid/legacy `--send-input` must remain blocked and cannot fall through to the old quote/confirm coordinator. Other supported schedule/control commands fall through unchanged.
- `broadcast-client.ts`: `createBroadcastClient` requires the existing authenticated `resolveWorkspaceId`, the same configured Core origin/fetch/bearer and a durable `BroadcastRequestStore`. Use the ordinary existing login/catalog boundary; no alternate authorization path is supplied.
- `broadcast-approval.ts`: after explicit user approval of the exact ready review, call `approvedBroadcastSendInput` to produce the reference-only input for the existing `--send-input` spelling. A new review can be obtained with `broadcast review`; same-input recovery is `broadcast send recover` with exact workspace/environment/draft/request ID. Manual observation uses `broadcast operation` and the returned URI.
- `mcp-broadcast-bg-tools.ts`: compose `registerMcpBroadcastBgTools` once into the existing authenticated session. Replace the current normal `fonte_prepare_broadcast`, `fonte_send_broadcast` and `fonte_read_broadcast_send_operation` registrations, avoiding duplicate names. Preserve draft/HTML authoring and scheduling/control tools. `fonte_prepare_broadcast` now calls the one server-owned BG review operation; the old grant-coordinating paved prepare is not another normal path. Exact request recovery is `fonte_recover_broadcast_request`. Send/recovery annotations declare destructive intent because they can submit an approved Send.
- `broadcast-file-store.ts`: configure one consistent per-user request directory for CLI and MCP. It stores no bearer. Browser-safe client interfaces are separate from this Node filesystem adapter.
- Export the client wire/types/builders through the owned product package composition. The existing package file allowlist already includes built `dist` files, but no package export or activation is changed here.
